## 0. 摘要

**问题。** 给定一个在源水域数据上训练好、且不得在目标域使用任何标签的增强模型，测试时自适应（TTA）在目标水域的每一张图上做一次参数更新。更新有时有益、有时有害，且事先未知。本文不提出新的增强网络，只研究**提交规则**：在因果（不看未来帧）、无标签、可审计、可回滚的约束下，逐图决定"接受这个更新 / 拒绝并保持 / 回滚到源模型"。

**设计。** 三条预先锁定的跨域迁移（LSUI→UIEB、UIEB→LSUI、LSUI→UFO-120），统一 256×256 整图评测，因果 prequential 协议，9 条对照臂（含强冻结模型、固定阈值门、等接受率随机门、随机重置、逐图 oracle 上界）。控制器只用 19 条无标签证据通道，在**目标域开发集**上做 5 折交叉拟合的校准，阈值以"误接受率 FAR ≤ 0.10 且保留收益最大"选取；若交叉拟合 AUROC < 0.5，控制器**声明弃权**（一张都不接受），而不是偷偷退回一个好看的数字。

**结果（三条迁移均已完成，n = 89 / 428 / 120）。**

1. **UIEB→LSUI 与 LSUI→UFO 上，门控把适配的伤害压低了约 0.54 dB / 0.14 dB**，并把尾部伤害显著收窄：最差 10% 的 ΔPSNR 从 −0.0969 → −0.0404 dB、−0.0827 → −0.0271 dB；负迁移比 NAR₀ 从 0.463 → 0.114、0.592 → 0.192。
2. **但两条迁移上"无条件适配"本身就是负收益**（相对冻结源模型 −0.73 dB / −0.19 dB），门控只是把损失变小（−0.19 dB / −0.05 dB），**始终没有超过"根本不适配"**。因此本研究的正确定位是"损伤限制器"，不是"增益放大器"。
3. **主迁移 LSUI→UIEB 上，开发集证据没有预测力**（交叉拟合 AUROC 0.458），弃权规则如实触发：接受率 0，结果等于源适配器。这是被 §9 预先声明的风险，不是事后解释。
4. **§11 交付判定：`fail`（24 通过 / 4 失败 / 0 不可验证，共 28 门）。** 四个失败全部在主迁移，其中最硬的一条是 PSNR 相对差 5.10%（20.9361 vs 22.0612 dB，绝对差 −1.1251 dB），恰好越过 5% 容差。四个状态字段分开报告：performance `fail`(5/6)、risk_control `fail`(9/12)、reproducibility `pass`(6/6)、novelty `documented_not_machine_checkable`。
5. **两个负结果同样有价值**：(a) 再退化（re-degradation）残差作为"无标签验证器"被证伪——用它筛选比不筛差 3.6–5.0 dB，且与真实 ΔPSNR 反相关（Spearman −0.43 / −0.36）；(b) 统计量匹配（source RGB/Lab 先验、grey-world、gamma）在开发集上损失 0.5–1.8 dB，而逐图仿射校正值 +6.9 dB、数据集级仿射只有 +0.17 dB——缺失的信息确实是**逐图颜色校正**，不是全局色偏。

## 1. 研究问题与判定边界

### 1.1 场景

源模型 $f_\theta$（MambaCue，2,244,946 参数，已冻结）在源水域数据上训练。部署到目标水域后，样本以流的形式到达，**没有标签，也不允许回看未来**。允许的操作只有：用当前无标签输入做一次自监督更新，得到候选参数 $\theta_t^{+}$，然后决定是否提交。

### 1.2 边界（明确不做什么）

- 不训练新的增强骨干；不改源模型权重。
- 不使用目标域测试标签做任何选择、阈值或早停。
- 不把"目标域监督训练过的模型"当作主对比对象（它们只作为坐标另列）。
- 不做在线超参搜索；不引入额外的人工标注。

### 1.3 可审计的定义

一次"提交"必须可重放：给定相同的流、相同的种子、相同的动作序列，输出必须逐位（到浮点噪声底）复现。这条要求直接决定了实现里必须显式播种（§2.9）。

## 2. 实验设计

### 2.1 数据与划分

数据根目录 `/home/user/UnderWaterDataset`，每对为 `input/` 与 `GT/` 同名图像。

| 数据集 | 训练 | 开发（dev） | 测试（test） | 分辨率 | 说明 |
|---|---|---|---|---|---|
| LSUI | 3,423 | 428 | 428 | 320×240 – 1280×1024 | 真实水下场景，配对的 GT |
| UIEB | 712 | 89 | 89 | 800×450 / 640×360 | 真实水下，配对 |
| UFO-120 | 1,200 | 300 | 120 | 输入 320×240 / GT 640×480 | **全部为 2 倍超分对**（`sr_pair_fraction = 1.0`，1200/300/120 全部尺寸不一致） |

三条迁移共用同一套划分，**dev 只用于校准与选择，test 只跑一次**：

| 迁移 | 源（训练） | 目标 dev | 目标 test |
|---|---|---|---|
| LSUI→UIEB | LSUI/train (3,423) | UIEB/dev (89) | UIEB/test (89) |
| UIEB→LSUI | UIEB/train (712) | LSUI/dev (428) | LSUI/test (428) |
| LSUI→UFO | LSUI/train (3,423) | UFO/dev (300) | UFO/test (120) |

数据审计（`runs/manifests/data_audit.json`）记录每个划分的样本数、尺寸直方图、尺寸不一致对数与流摘要（如 `LSUI/test` = `63f48000…`、`UIEB/test` = `6837ea16…`、`UFO/test` = `e9a2a1b0…`）。UFO 的尺寸不一致（1200/300/120）正是超分任务的标志：**在 256×256 统一协议下，超分难度被重采样抹掉，所以本文的 UFO 结果是"增强"而非"超分"**，这一点在报告中如实标注，不与 UFO-120 的超分 SOTA 直接比。

### 2.2 统一评测协议

- 输入与 GT **整图**缩放到 256×256（双三次，`reducing_gap=3`），**不裁剪、不填充**；GT 用同一变换。
- 所有方法共享同一个样本顺序（`shuffle`，`seed=0`），同一份输入张量缓存，避免"重采样差异"变成方法差异。
- 256 之外的原生分辨率轨道**未执行**（见 §5 局限），因此所有数字只在 256×256 坐标内可比。

### 2.3 因果 prequential 协议

对时间步 $t = 0,1,\dots,n-1$：

```
y_pre  = f(x_t; θ_t)                  # 用已提交状态先输出
cand   = Adapt(θ_t, x_t)              # 用当前输入（及可选记忆）产生候选
y_plus = f(x_t; cand)                 # 候选在同一张图上的输出（只用于算证据与诊断）
e_t    = Evidence(x_t, y_pre, y_plus, θ_t, cand)     # 19 条无标签通道
a_t    = π(e_t)                       # accept / keep / reset
θ_{t+1} = cand if a_t = accept else (θ_0 if a_t = reset else θ_t)
y_post = f(x_t; θ_{t+1})              # 提交后、同一张图上的输出（realised 视角）
```

三条不变式，代码层面强制：

1. **不看未来**：`Evidence` 与决策只依赖 $x_{\le t}$ 和 $\theta_t$；测试标签只在记录度量时使用。
2. **同序**：所有 9 条臂共享同一 `stream_digest` 与样本顺序。
3. **状态只在提交时变**：`reset` 回到的是**已发布的 $\theta_0$**，回滚是精确的（§2.9 的 C5 检查逐位验证）。

### 2.4 系统与超参数

| 项 | 值 |
|---|---|
| 骨干 | MambaCue（冻结），2,244,946 参数 |
| 适配器 | 残差式：`conv1(6→32,k3) → conv2(32→32,k3) → conv3(32→3,k3)` + `affine(6→6)`，**11,917 参数**；`conv3`/`affine` 零初始化 |
| 前向 | `clamp(backbone(x) + adapter(x, backbone(x)), 0, 1)` |
| θ₀ | 骨干 + **已发布的源适配器**（不是裸骨干；因此 reset 回到"发布检查点"） |
| 每步内层更新 | `steps=1`，`lr=1e-3`，`weight_decay=0`，`grad_clip=1.0` |
| 自监督损失 | 一致性项：输入做光度扰动 $b\sim U(-0.10,0.10)$、$c\sim U(0.85,1.15)$，最小化两视图输出差；`memory=0`，`reset_every=0`，`ema=0.9`（无记忆时仅作参考） |
| 随机性 | `seed=0`；每次内层更新用 `(seed, t, k)` 派生的独立 `torch.Generator` |

适配器之所以这么小，是刻意的：它的目标是"可被门控的低维修正"，不是第二个增强器。11,917 参数在 2.24M 冻结骨干上只允许小幅偏移，这也解释了 §3 中"每次更新的 ΔPSNR 量级只有 0.01 dB、单图尾部却可达 −0.1 dB"的现象。

### 2.5 九条对照臂

| 臂 | 定义 | 用了什么信息 | 作用 |
|---|---|---|---|
| `source_frozen` | 不更新，直接用 $\theta_0$ | 无 | 下界参照（"不适配"） |
| `source_adapter` | 加载发布适配器但**不更新** | 无 | 区分"适配器本身"与"在线更新" |
| `always_accept` | 每个候选都提交 | 无 | 上界风险参照（无条件 TTA） |
| `stochastic` | 以 $p$ = 门控实测 reset 率随机回滚（CoTTA 式） | 仅速率 | 正则化器对照 |
| `random_gate` | 固定 $p=0.5$ 随机接受 | 仅随机数 | 无信息门 |
| `random_matched` | 以门控**实测接受率**随机接受 | 仅速率 | **H5 关键对照**：同速率、零信息 |
| `simple_gate` | 仅当代理损失下降超过 τ 才接受（单通道、单阈值） | 1 条通道 | 最简非平凡门；多信号若胜不过它，说明证据分解无价值 |
| `ours` | 19 通道 + 5 折交叉拟合控制器 | 无标签证据 | 本文方法 |
| `oracle` | 逐图看 GT 后决定（有益才提交） | **测试标签** | 不可部署的逐图上界 |

`oracle` 与 `random_matched` 是诊断臂，**永不作为 §11 门控的参照**（`08_comparison.py` 的 `DIAGNOSTIC_ARMS`）。

### 2.6 证据通道（19 条，全部无标签）

`upd_step_norm, upd_rel_anchor, upd_l2_anchor, upd_l2_cur, loss_ss, dloss_ss, dloss_redeg, grad_cosine, clip_ratio, dout_src, dout_cur, hf_resid, contrast_ratio, sat_mean, color_balance, redegrade_t, redegrade_src, redegrade_cur, dredeg_src`

覆盖五类：自监督损失与其梯度、再退化残差、扰动一致性、输出/颜色/高频变化、更新幅度与锚点距离。它们被刻意做成"与动作无关"的量：候选一产生就记录，**不因 keep/reset 而变成 0**（这正是修复前统计污染的原因，见 §2.7）。

### 2.7 控制器训练与校准（只用 dev）

1. 在 **dev** 的 always-accept 提议池上，每条候选记录 19 通道 + 两个标签：`mse_delta = d_local > 中位数`、`psnr_drop = ΔPSNR_cand < 0`。
2. **5 折交叉拟合**：每折在训练部分按 |AUC−0.5| 选 top-$k$，在训练部分拟合类平衡逻辑回归（L2 = 1e-2），在留出部分出概率；$k \in \{3,5,19\}$ 由**折外 AUROC** 选择。
3. 阈值 $\tau$：在所有折外概率上取"FAR ≤ 0.10 且保留收益最大"的切点；`reset_threshold` 取更保守的切点（超过即回滚）。
4. **弃权规则（预先声明）**：若最佳折外 AUROC < 0.5，令 $\tau = -\infty$、`mode = abstain_no_signal`、`reset_threshold = 1.01`——一张都不接受，并把这个事实写进 `risk_controller.json`，而不是悄悄换一个阈值。

三流实测（`runs/risk_*/risk_controller.json`）：

| 迁移 | mode | k | OOF AUROC | τ | reset τ | 选中通道 | 正类率 |
|---|---|---|---|---|---|---|---|
| LSUI→UIEB | `abstain_no_signal` | 19 | **0.4581** | −∞ | 1.01 | 19 条全选 | 0.494 |
| UIEB→LSUI | `risk_controlled` | 5 | **0.7095** | 0.3171 | 0.4671 | hf_resid, loss_ss, dloss_redeg, contrast_ratio, redegrade_src | 0.500 |
| LSUI→UFO | `risk_controlled` | 19 | **0.7324** | 0.2548 | 0.4048 | 19 条全选 | 0.500 |

δ（风险事件阈值）取 dev 上 `d_local` 的中位数：−2.129e−05 / +2.992e−06 / +1.586e−06（MSE 单位）。

### 2.8 指标

逐图计算，再对 $n$ 张图汇总（统计单位 = 一张图，配对比较）：

| 指标 | 定义 | 视角 |
|---|---|---|
| PSNR / SSIM / MSE | 整图，对 GT | 绝对 |
| ΔPSNR (realised) | $\mathrm{PSNR}(y_{post}) - \mathrm{PSNR}(y_{pre})$，keep/reset 恒为 0 | 流实际经历 |
| ΔPSNR (candidate) | $\mathrm{PSNR}(y_{+}) - \mathrm{PSNR}(y_{pre})$，与动作无关 | 提议本身的价值 |
| worst-10% ΔPSNR | 最差十分位的均值 | 尾部风险 |
| NAR₀ / NAR₀.₁ / NAR₀.₅ | ΔPSNR < 0 / −0.1 / −0.5 dB 的比例 | 负迁移率 |
| accept / keep / reset | 三种动作的频率 | 行为 |
| FAR | 在**候选有害**的样本中被接受的比例 | 误接受率 |
| beneficial false reject | 在候选有益的样本中被拒绝的比例 | 漏接受率 |
| benefit retention | 接受的候选收益 / 全部候选正收益 | 收益保留 |
| regret | 与逐图 oracle 的 ΔPSNR 差 | 决策损失 |

**关键区分**：realised 视角回答"这条流最后好不好"，candidate 视角回答"这个门会不会看走眼"。修复前两者被混为一谈（keep/reset 被记成"无害"），导致 NAR₀ 恒为 0——本报告全部风险统计均以 candidate 视角为准，并在表中两列并列。

### 2.11 预注册假设

| id | 假设 | 证伪条件 |
|---|---|---|
| H1 | 两个参照（相对当前模型 / 相对源模型）在相当比例的更新上符号相反（≥25%） | <10% 则"双参照"是装饰 |
| H2 | 无标签证据对"本次更新是否有害"的预测优于随机 | 留出 dev 上 AUROC ≈ 0.5 |
| H3 | 门控在 worst-10% ΔPSNR 与 NAR 上优于 always-accept | 无改善 |
| H4 | 门控保留收益（对 oracle 有益样本的接受率 ≥50%） | <50% |
| H5 | 门控增益能通过等接受率随机重置对照 | 同速率随机门不可区分 |

### 3.2 逐迁移判读

**LSUI→UIEB（主迁移，弃权）。** 开发池 n = 89、有害率 39.3%，19 条通道的折外 AUROC 只有 0.4581（标准误约 0.06，低于 0.5 约 1.3σ）。控制器按预注册规则弃权：`keep` 89 张，`ours` 与 `source_adapter` 完全相同。此时 realised ΔPSNR 恒为 0，worst-10% 与 NAR₀ 为 0——**这 0 不是"零风险"，而是"零动作"**；`random_matched` 因接受率自动取 0 而与 `ours` 重合，不能作为证据。真正有意义的是 candidate 视角：候选本身平均 +0.0136 dB、39% 有害，说明池子里有机会，只是没有可用的信号去挑。

**UIEB→LSUI（门控起作用）。** 这是唯一"三件事同时成立"的迁移：折外 AUROC 0.7095（5 通道）；接受 18.7% / 保持 18.0% / 回滚 63.3%；realised ΔPSNR +0.0035 dB（`always_accept` +0.0081，但它的绝对水平是 21.4473，比冻结低 0.73 dB）；最差 10% −0.0404（对比 −0.0969）；NAR₀ 0.114（对比 0.463）；FAR 0.088（接近校准目标 0.10）；收益保留 0.191，regret 0.0143 dB/图。**它把"灾难式适配"变成了"温和的轻微损伤"**，但没有变成正收益：21.9886 仍低于冻结的 22.1777。

**LSUI→UFO（门控靠回滚）。** 折外 AUROC 0.7324，但接受 22.5% / 回滚 54.2%；FAR 0.232，说明它对"有害候选"的识别并不好（有害被接受率甚至略高于有益：23.2% vs 21.6%）。它之所以把尾部从 −0.0827 压到 −0.0271，主要靠**高回滚率**把状态频繁拉回 θ₀，而不是靠"选得准"。等接受率随机对照（below）也支持这一点：随机门在 17.5% 接受率下拿到 −0.0262 的尾部，比 `ours` 还好。

## 4. 讨论：为什么门控只能"止损"

1. **头寸太小。** 开发集选出的适配预算（1 步 × 1e-3）只值 0.088 dB 的 oracle 上限（`docs/research_plan.md` §7），而 19 通道证据的噪声量级与它相当。信号与噪声同阶时，任何门控的期望收益都接近 0；更激进的预算（3 步 × 3e-3）虽有 1.56 dB 上限，但基线本身被压低 0.6 dB，净收益更差。
2. **校准目标与任务目标错位。** FAR ≤ 0.10 是在约 50% 有害基率下的保守约束，它保证"少犯错"，代价是拒掉大量有益更新（H4 被证伪：接受率 21.6–27.8%，远低于 50%）。若改成"最大化净收益"，就需要对收益幅度建模，而不仅是分类有害/有益——本文没有做，这是明确的后续方向。
3. **弃权是正确行为，不是失败。** 主迁移上证据无预测力时，拒绝动作让结果等于"不折腾"；把它包装成"零风险"才是造假。验收脚本专门加了 `active` 前置条件与 `positive_gain` 门来防这件事。
4. **与既有工作的差别**：DCTTA（CVPR'26）用一次性 Fisher 掩码 + 伪标签，没有接受/拒绝、没有 θ₀ 锚、没有回滚；Wakayama（ICML'26）从决策论给出"何时/多大幅度/哪个方向"并带 PAC-Bayes 保证，本文只在稠密复原任务上做操作化，不宣称拥有该理论；Schirmer（NeurIPS'25）是流级风险监控与告警，不是逐更新反事实；PORTAL（2026）选择固定预测规则且需要标签；D2TTA（ICASSP'26）是低层复原的持续 TTA，带不确定性过滤但没有逐更新效用与锚项。本文的差异点是**逐更新、无标签、双参照（局部 + 锚）、可回滚、可重放**，以及**把失败如实报出来**。

---

## 5. 威胁与局限

1. **上游权重来源不可考。** MambaCue 权重的训练语料未文档化，"zero-shot"只是操作性声明（我们未在目标域训练），不等于上游没见过这些数据。
2. **θ₀ 是已发布的源适配器**，不是裸骨干；因此 reset 回到发布检查点，所有"相对冻结"的比较都以它为基准。
3. **原生分辨率轨道未跑**，所有结论限定在 256×256 整图坐标；UFO 的超分属性被重采样移除。
4. **样本量小**：n = 89 / 428 / 120；主表未做置信区间，H2 的 0.458 与 0.5 只差约 1.3σ，不能断言"反向信号"，只能断言"无可用于门控的信号"。
5. **单一骨干、单一适配器族、单一随机种子**；未做多种子方差分解，因此"门控 vs 随机"的 0.0035 vs 0.0010 dB 差异不能外推为稳定效应。
6. **`stochastic` 在主迁移上与 `always_accept` 完全重合**（reset 率为 0 导致 p = 0），该行的"持平"不构成"随机重置无效"的证据。

---

## 6. 结论

- 在三条锁定迁移上，**无标签逐更新风险控制可以把 TTA 的伤害压小、把尾部收窄，但没有在任何一条上把 TTA 变成正收益**；主迁移甚至无可用信号，只能弃权。
- 因此 §11 判定为 `fail`，且这是**测量结果**而非脚本缺陷：唯一的硬指标失败是 5.10% vs 5% 容差（−1.13 dB）。
- 真正可复用的产出是：一套可重放的因果 prequential 评测栈（重放 0.0 dB）、一个带弃权语义的校准流程、一组诚实到能自我证伪的对照（等接受率随机门、逐图 oracle、强冻结参照），以及两个明确的负结果（再退化验证器、统计量匹配）。
- 下一步（若要翻盘）：把"是否提交"升级为"提交多少"（对更新幅度做回归而非分类），并把证据从 19 条手工通道换成学习到的逐图校正参数预测；预算上需要先找到 oracle 上限 ≥1 dB 且基线不被压低的适配器配置。
